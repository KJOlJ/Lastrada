# Web workflow regression checks

The listening stage checks recording reuse and separate replay/re-singing. A
recording sample does not imply a separate replay. Confirm the recording sample
and its suggested times, and choose **No separate replay or re-sung part** if
that use did not happen. No timestamps or sound details are required for a use
marked absent. At least one use must be present to generate this document.

When Next is blocked, the alert scrolls into view and names the missing decision
or time confirmation. The second rights check keeps its own heading. Status
selects persist on their `change` event, independently of `input` event ordering.
Later stages still require sound/placement details and explicit review before
export. Missing original-track timestamps do not prevent accepting valid
new-track fallback times; unknown source positions remain unknown.

## Automated browser test

```bash
PYTHON=.venv/bin/python npm test --prefix web
```

This tests filename prefill, an unresolved replay check, visible blocking
instructions, change-only select events, unconfirmed timestamps, accepting
recording times, skipping absent replay, sound and placement details, Python
review validation, approved HTML download, and resume after reload.

Google identity, cloud uploads, job transport, and user review actions are
simulated. The Python review and document rendering rules are real. This is not
a live cloud integration test or a human listening review.

To run the same workflow on an already generated private analysis:

```bash
LASTRADA_BROWSER_ANALYSIS=/absolute/private/analysis.json \
LASTRADA_BROWSER_OUTPUT=/absolute/private/browser-output \
PYTHON=.venv/bin/python npm test --prefix web
```

The first path contains an `Analysis` JSON generated by the real pipeline. The
optional second path receives a test-reviewed HTML document and final-screen
screenshot. Keep both paths outside tracked files (for example in ignored
`outputs/private/`). Test-entered descriptions are fixtures, not verified musical
claims. The test still mocks authentication/upload transport and loads the saved
analysis; it does not upload audio to Firebase or rerun detection.

## Hosting update

These workflow fixes change frontend JavaScript, not the analysis service. A
Hosting-only deployment can update the existing site without rebuilding the
worker. Use the intended project/site explicitly, preserve its generated
`web/public/config.json`, and verify the deployed app after publishing. A pushed
Git commit alone does not update Firebase Hosting.

For the existing `lastrada-64bab` deployment, from its Cloud Shell checkout:

```bash
git pull --ff-only origin feat/firebase-web
test -f web/public/config.json && npx --yes firebase-tools@15.4.0 deploy --only hosting --project lastrada-64bab
```

The checked-in Hosting configuration explicitly selects `lastrada-64bab`. If
`config.json` is missing, this command stops before deployment; recover the
existing generated configuration rather than publishing an unconfigured UI.
This replaces that site's current frontend and does not deploy Cloud Run.

## Optional instrument check

The listening screen has one visible **Run instrument check** button. It shows
starting, queued and running feedback immediately within the same screen, keeps
review entries, and disables duplicate clicks. Completed comparisons appear in
a table. A cached result is displayed without another request. If there are no
paired original/new-track timestamps, the unavailable button explains why.

Worker failures (even when the main analysis remains completed), model-download
failures, quota refusals and empty results are shown beside the control. An
optional failure does not block the main document workflow. Reload reconnects
to an existing queued job. Starting a new sample ignores late responses from
an earlier request. Stem estimates remain possible supporting evidence.

Run these generated-data browser scenarios with:

```bash
PYTHON=.venv/bin/python npm run test:instruments --prefix web
```

The suite covers successful/cached results, worker and model failures, quota
refusal, completed comparisons with no match, empty results, missing source
times, and reset during a request. Except for the reset scenario, each continues
through review and actual Python document rendering to HTML download. Cloud
transport and identity are mocked, so hosted worker execution still requires
verification in the deployed app.
